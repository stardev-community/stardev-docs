Sistem lisensi untuk APK dan mod APK

APK tidak punya server sendiri, jadi verifikasi harus keluar ke satu endpoint HTTPS. Yang menentukan kualitas sistemnya bukan API-nya, tapi bagaimana aplikasi bersikap saat jaringan mati atau HWID berubah.

HWID yang stabil di Android

Kombinasi paling aman: Settings.Secure.ANDROID_ID + nama model + paket aplikasi, lalu di-hash. Jangan pakai IMEI (butuh izin dan diblokir di Android 10+), dan jangan pakai nilai yang berubah setiap instal ulang.

val raw = Secure.getString(contentResolver, Secure.ANDROID_ID) +
          Build.MANUFACTURER + Build.MODEL + packageName
val hwid = MessageDigest.getInstance("SHA-256")
    .digest(raw.toByteArray()).joinToString("") { "%02x".format(it) }

Kontrak endpoint

Satu request, satu jawaban JSON. Simpan hanya field yang benar-benar dipakai aplikasi: valid, expiresAt, dan pesan error.

POST /api/verify
{"key":"XXXX-XXXX","hwid":"a1b2...","app":"my-mod"}

200 {"valid":true,"expiresAt":1767225600,"plan":"user"}
200 {"valid":false,"message":"HWID limit reached (1/1)"}

Kapan butuh sistem sendiri

Kalau kamu menjual banyak key dan sering menangani permintaan reset perangkat, panel admin sendiri menghemat waktu. Kalau hanya beberapa pembeli, layanan hosted sudah cukup.
