GUIDE · ANDROID

APK license system that survives real users

Mobile licensing fails in the boring cases: no signal on a train, a reinstall, a cheap device with a reset ID. Design for those three and the rest is bookkeeping.

A HWID that does not change weekly

Hash a combination of ANDROID_ID, manufacturer, model, and package name. Avoid IMEI — restricted since Android 10 — and avoid values regenerated per install.

String raw = Settings.Secure.getString(cr, Settings.Secure.ANDROID_ID)
           + Build.MANUFACTURER + Build.MODEL + getPackageName();
String hwid = sha256(raw);

Offline behaviour

Never let "no network" mean "full access forever". Cache the last successful response with its expiry, allow a bounded grace window (hours, not weeks), then close.

Endpoint contract

POST /api/verify
{"key":"XXXX-XXXX","hwid":"a1b2...","app":"my-app"}

200 {"valid":true,"expiresAt":1767225600,"plan":"user"}
200 {"valid":false,"message":"Key expired"}

Two fields are enough for the client. Everything else — plans, notes, device history — stays server-side.

Reset policy

Give each key one or two self-service resets, then require admin approval. Unlimited resets turn a device limit into decoration.
